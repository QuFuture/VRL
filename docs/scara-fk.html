Theory

Each link transform follows the standard Denavit–Hartenberg convention:

Aᵢ = Rot(z,θᵢ)·Trans(z,dᵢ)·Trans(x,aᵢ)·Rot(x,αᵢ) ⎡cθ −sθcα sθsα a·cθ⎤ Aᵢ = ⎢sθ cθcα −cθsα a·sθ⎥ ⎢0 sα cα d ⎥ ⎣0 0 0 1 ⎦

The tool pose is the product T₀⁴ = A₁A₂A₃A₄. For a SCARA it reduces to a closed form:

x = a₁cosθ₁ + a₂cos(θ₁+θ₂) y = a₁sinθ₁ + a₂sin(θ₁+θ₂) z = d₁ − d₃ − d₄ φ = θ₁ + θ₂ − θ₄

Procedure

  1. Press Home and note that the arm lies straight along x₀ with x = a₁ + a₂ = 0.600 m.
  2. Change only θ₁. Confirm that x and y change but z and the distance from the base axis stay fixed.
  3. Change only d₃. Confirm that only z changes, by exactly the amount you entered.
  4. Change θ₄ and watch φ. Explain why z₄ points downward.
  5. Choose a pose, compute T₀⁴ by hand from the DH table, and compare with the matrix shown.
  6. Find two joint sets (elbow up and elbow down) that give the same x, y. Log both.

How this simulator is built

  • The DH table is stored as data. Each slider change rebuilds A₁…A₄ with the formula on the left and multiplies them.
  • The 3D arm is a three.js scene graph whose groups mirror the joints: base → link 1 (θ₁) → link 2 (θ₂) → quill (d₃) → wrist (θ₄).
  • The tool frame triad is placed directly from the computed T₀⁴, so if your math were wrong it would visibly miss the gripper.
  • The workspace is drawn by sampling every θ₁, θ₂ pair within the joint limits.
